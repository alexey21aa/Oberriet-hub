# Работа администратора

Доступ — `/wp-admin/`, штатный WordPress, роль administrator/manage_options, TOTP. Регистрации жителей и публичного кабинета нет. Редакторы WordPress не имеют доступа к данным Hub. Админка не кешируется.

Меню **Oberriet Hub** показывает число услуг/контактов/событий/источников, missing/stale translations, источники для проверки, агрегаты за 7 дней и последние технические журналы. Никакие сырые поисковые фразы и черновики жителей не должны появляться в таблицах.

В подменю Services / Places / Events / Guides / Contacts / Sources доступны штатные записи WordPress. Редактируйте `Record JSON`: удобнее скопировать аналогичную запись из экспорта. Сохранение проверяет ID, языки, email, allowlist URLs и nonce/capability. Текст выводится через escaping; HTML в редакционных полях не исполняется. Немецкий текст — исходный: изменения title/description DE автоматически ставят EN/RU/UK в `stale`.

## Услуги

Минимальная структура есть в `data/seed.json`. Сохраняйте `id`, `title` и `description_short/description_full` на четырёх языках, `topic`, `locality`, `authority`, `contact`, `official_url`, `source_id`, `source_url`, `source_checked_at`, `source_trust_level`, `translation_status`. Контакт должен существовать в Contacts. `requirements`, `fee`, `processing_time`, `eligibility`, `documents` оставляйте null, если факт не подтверждён. Не путайте доступность записи в каталоге (`routing-metadata`) с полной проверкой условий услуги (`page`). Дату проверки менять только после проверки человеком.

`status=checked` не означает юридическую гарантию. Черновики записей сохраняйте в WordPress как Draft: публичные данные берутся только из Published. Переводы имеют `draft/checked/stale`; их официальность не заявляется. `oh_guide` доступен для отдельных руководств; исходные справочные материалы также находятся в Services и участвуют в поиске.

## События

`date`, `end_date` — ISO YYYY-MM-DD; конец хранится включительно, ICS экспортирует следующий день как exclusive end. `title`/`description` — четыре языка, `locality` — одна из пяти местностей или all, `type` — culture/school/waste. Указать location и официальный источник. Не использовать время открытия дверей как начало концерта. В этой версии экспорт — all-day dates; точное время и timezone ICS — задача следующей версии. Истёкшие события не показываются автоматически.

## Источники

У Sources `source_id`, HTTPS `source_url`, domain, authority, trust_level A/B/C/D, last_checked, ttl_days, review_status и заметка о reuse. A — органы власти; B — публичные учреждения; C — организации; D — community. Не приписывать Hub государственный статус. Добавление домена в allowlist — осознанное изменение `Sources.php`, не поле ввода посетителя.

Ежедневный cron делает до пяти условных запросов к источникам с истёкшим TTL; redirects запрещены, timeout 10 секунд, тело ≤300 KB. Ответ/хеш меняет только флаг needs_review, а не юридические факты и не переводы. Для страниц, проверенных через публичную выдачу без прямого скачивания, http_status/hash могут быть null/пустыми: это честный provenance, а не выдуманный HTTP 200. Первый мониторинговый хеш тоже требует сверки человеком. После проверки обновить факты/дату, установить review_status=checked и очистить кеш.

## Отходы и намерения

На общей странице редактируется JSON Waste. Большой словарь Intents изменяйте через файл импорта/экспорта: при более чем 100 намерениях textarea не выводится. Отходы: valid_from/to, calendar_year, dates/locality, weekday, instruction на четырёх языках, source_id/URL/date. 2026 не переносить на 2027. Kobelwald: бумага для Berggebiet; для обычного мусора маршрут не выдуман и требует уточнения. Сохраняются только проверенные схемы.

Намерение 0.2: уникальный `id`, `service_id` существующей услуги, `kind`, `phrases` (DE/EN/RU/UK). Старый формат 0.1 с ID услуги напрямую поддерживается при импорте и сопоставляется с `original-ID`, без дублирования существующего редакционного намерения. В агрегатах считается этот ID, а не фраза посетителя. Ввод имени/адреса в поиске не становится аналитическим измерением. Синонимы добавлять редакционно, не копируя персональные запросы из журналов.

## Импорт/экспорт

Export выгружает опубликованный каталог, контакты, события, места, источники, отходы и намерения. Не включает пароли, логи, API-ключи, черновики писем или профиль WordPress. JSON/CSV importer ≤30 MiB (PHP upload/post limits должны быть достаточными), доступ manage_options + nonce; дубликаты пропускаются, overwrite заменяет совпадающие ID. Весь набор проверяется до начала импорта, включая ссылочную целостность источников и намерений. Большой импорт проходит через приватную очередь с сохранением прогресса; после ошибки устраните причину и возобновите из dashboard. Финальную стадию индекса дождитесь до complete; держите резервную копию перед overwrite. Импорт не удаляет отсутствующие записи.

## Письма и ИИ

Маршрутизация и редакционный немецкий шаблон работают бесплатно и локально. Copy/mailto не отправляют письмо сами. Для короткого сообщения о фонаре есть немецкая формулировка. Произвольное иноязычное описание сохраняет оригинал с пометкой: перед отправкой перевести/отредактировать его. Не обещать автоматический перевод произвольного текста без ИИ.

Необязательный AIProvider принимает только найденный проверенный контекст, выключен без трёх серверных constants и доступен только администратору. NullProvider сохраняет работоспособность без ключа. Результат платного/стороннего провайдера — черновик с обязательной проверкой; публичный чат в MVP не включён. Никакой диалоговой истории нет. Для включения потребуется выбор провайдера, бюджет, оценка трансграничной передачи и обновление Privacy.

## Обновление 0.2.0: большая база и очередь

Добавлены Organizations (включая учреждения/отделы), Answers, FAQ и Guides. В списках доступны стабильный ID, проверка источника, поиск/фильтры и массовая отметка checked/needs_review. Используйте штатный Trash для обратимого удаления.

JSON/CSV импорт теперь допускает до 30 MB на уровне приложения. Реальные ограничения PHP upload_max_filesize/post_max_size могут быть ниже: для файла целиком нужны не менее 32/34 MB, либо разбивайте импорт. Стартовая база импортируется из установленного плагина и не требует HTTP-загрузки. Очередь private/nonautoload, по 25 записей на запрос; закрытие страницы приостанавливает работу. Продолжение — Oberriet Hub → Continue / resume. Завершённой считается стадия complete после готовности индекса. Ошибка сохраняет выполненные записи: исправьте причину и повторите. Отсутствующие ID не удаляются.

CSV формат: collection,id,record_json. В record_json сохраняется полный объект с переводами и provenance. Коллекции: services, contacts, organizations, answers, faqs, guides, events, places, sources, waste, intents, aliases. Экспорт CSV/JSON имеет nonce/capability; частные журналы и credentials не экспортируются.

Большие словари намерений редактируйте через валидируемый импорт/экспорт, а не огромную textarea. Структурированное намерение имеет собственный id, service_id, kind и phrases; aliases имеют service_id, intent_id, language, phrase. Формулировки не являются отдельными услугами. После редактирования записи индекс обновляется; большие наборы обрабатывайте через очередь.

Реквизиты: operator, organization, responsible_person, address, phone, email, hosting_provider/country. Используйте только реальные значения. Публичный запуск и индексация требуют заполненных реквизитов и личного TOTP/recovery codes.

Необязательная кнопка локального ИИ появляется только при наличии браузерного LanguageModel. Она использует уже установленную модель, передаёт ей только найденные редакционные данные и не меняет официальный ответ. Модель автоматически не загружается; результат — отдельно помеченный непроверенный черновик. При любой недоступности остаётся детерминированный поиск.

Составные намерения имеют type=compound-navigation-goal, две tasks и ровно два answer_ids существующих ответов той же услуги. Они представляют комбинированную цель пользователя; не являются новыми услугами или фактическими ответами. Для повторного создания после основного генератора запустите scripts/extend-combinations.py на текущем объединённом seed.

При no-overwrite импорт объединяет намерения/формулировки, сохраняет существующий календарь и пропускает опубликованные записи с тем же stable ID. Для явной замены метаданных используйте overwrite только после резервного копирования. Старые ID намерений из пакета 0.1 сопоставляются с сохранёнными редакционными ID пакета 0.2.
